# Domain docs

Use a single-context layout: root `GLOSSARY.md` and `docs/adr/`.

Before domain exploration, read `AGENTS.md`, the root glossary when present, and ADRs relevant to the task. Use `README.md` for product context and `jev/QUESTIONS.md` when working on classification.

If the glossary or ADR directory is absent, proceed silently. Create them lazily when domain modeling resolves terms or decisions.

Use glossary terms consistently in issues, code, tests, and proposals. Surface conflicts with existing ADRs explicitly and explain any proposed revision.
